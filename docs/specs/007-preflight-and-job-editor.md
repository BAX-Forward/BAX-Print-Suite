# Spec 007: Preflight profiles and non-destructive job editor (Milestones M1/M2 extension)

Target repo: **github.com/BAX-Forward/BAX-Print-Suite**. Read `docs/ARCHITECTURE.md` (§2 Preflight stage, §3.3 `Inspector/1`) and Specs 001 and 002 first.

## Clean-room rule (read first)
Same as Spec 001. Build from this spec, ISO 32000-1/-2, ISO 15930 (PDF/X-1a, -3, -4), ISO 19005 (PDF/A), the Ghent Workgroup public specifications, and library docs. Don't copy any commercial preflight profile, check names, messages or editor layout. No commercial product names.

## Goal
1. **Preflight profiles** that run `Inspector` plugins at intake and decide whether a job is `ready` or `held`.
2. An optional, external **normalization** step.
3. A **job editor**: per-job geometric and production edits stored as parameters, never baked into the source PDF.

## User stories
- As an operator, I want low-resolution images and missing fonts caught before I waste material.
- As a shop owner, I want different checks for different hot folders (fine art vs. vehicle wrap).
- As an operator, I want to scale, rotate, mirror or add bleed to a job without opening a design app, and undo it later.

## Functional requirements
- **FR1 Checks** (each returns findings `{checkId, severity: info|warn|error, page?, objectRef?, message, data}`):
  - page boxes present and consistent (TrimBox ⊆ BleedBox ⊆ MediaBox, ISO 32000 §14.11.2);
  - finished size vs. the target medium's printable width (both orientations);
  - effective image resolution at final size (ppi after CTM and job scale);
  - fonts embedded (or outlined);
  - color spaces used and named colorants (Separation/DeviceN), including the cut-contour names configured in Spec 004 `CutConfig`;
  - transparency, overprint, and output intent presence;
  - PDF/X or PDF/A conformance claims (version keys and required entries only; full validation is a plugin).
- **FR2 Preflight profile (our JSON schema):** list of enabled checks with thresholds and severity mapping. Defaults justified:
  - effective resolution warn < 100 ppi, error < 50 ppi at final size: wide-format viewing distance is typically ≥ 1 m, where ~100 ppi is near the eye's resolving limit and 50 ppi shows visible pixelation;
  - missing font: error (output becomes unpredictable);
  - missing TrimBox: warn, and MediaBox is used.
  Profiles bind to hot folders (Spec 001) or are chosen per job. Any `error` finding moves the job `inspecting → held` with reason `preflight`.
- **FR3 Normalization (optional):** an `Inspector.fixup()` implementation via an external engine (e.g. user-installed Ghostscript under ADR-0004) that rewrites to a chosen PDF/X level. Output is a new stored file; the original is kept. Never required for any other feature.
- **FR4 Job edits** (`JobTicket.edits`, applied in order at layout time):
  - `scale` (percent, or fit to width/height of a target), `rotate` (0/90/180/270), `mirror` (horizontal, for backlit or reverse-printed film),
  - `crop` to a box, `addBleed` (mm; edge-pixel extension or mirrored extension), `pageSize` override for edge-to-edge output,
  - `copies`, `spotMap` (rename or merge a named colorant to another name or to process), production metadata (customer, order number, cost centre) as free key/values.
  Every edit is reversible by removing it; the editor shows the stack.
- **FR5 Re-inspection:** after edits, size and resolution checks rerun against the edited geometry; findings update.
- **FR6 Preview:** the dashboard renders edits on the pdf.js preview using the same transform code (shared module) as layout, so preview and output agree.

## Acceptance tests
1. **Unit (Vitest):** for each check a passing and failing fixture **generated by our scripts** (pdf-lib): a 72 ppi image placed at 200 % → error; an unembedded font → error; TrimBox outside MediaBox → error; a `/Separation /CutContourTest` colorant listed when configured.
2. **State:** a job with an error finding ends in `held` with reason `preflight`; clearing (override with reason, logged in audit) moves it to `ready`.
3. **Edits:** `applyEdits` property test: rotate 90 four times = identity; scale then inverse scale = identity within 1e-9; mirror twice = identity. Effective ppi recomputed correctly after scale.
4. **Preview parity:** render preview and imposed output of an edited fixture with pdf.js; sampled pixels at 9 grid points match ±3/255.
5. **Differential (own fixtures):** run our corpus through our inspector and, where installed, an independent open-source validator (e.g. veraPDF for PDF/A, MPL/GPL dual, run as an external program) and compare the set of conformance verdicts; disagreements are reported, not failed.
6. Lint, license, vendor-neutral checks pass.

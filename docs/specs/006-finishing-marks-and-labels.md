# Spec 006: Finishing marks and job labels (Milestones M3/M4 extension)

Target repo: **github.com/BAX-Forward/BAX-Print-Suite**. Read Spec 003 (Part B marks hook) and Spec 004 (Part D registration marks) first.

## Clean-room rule (read first)
Same as Spec 001. Build from this spec, ISO 32000 (PDF optional content, Form XObjects), ISO/IEC 18004 (QR Code), ISO/IEC 16022 (Data Matrix), and generic finishing practice (grommeting, hemming, sewing, folding, trimming). Don't copy any commercial RIP's mark set, label layout, template syntax or option names. No commercial product names.

## Goal
`packages/marks`: a generator that adds **finishing marks** and a **job label** to an imposed layout without touching the source artwork, and exposes the same geometry as metadata for cut export and finishing staff.

## User stories
- As a finisher, I want grommet positions printed on a banner so I punch them in the right places without measuring.
- As a sewer, I want a hem or sew line printed where the fold or seam goes.
- As a trimmer, I want crop marks outside the bleed that don't print into the artwork.
- As a cutter operator, I want a machine-readable code on each print so the right cut file is loaded automatically.
- As a packer, I want a human-readable label telling me the job, customer, size and copy count.

## Functional requirements
- **FR1 Mark kinds** (all vector, generated by us):
  - `crop`: corner lines outside the trim box, offset beyond the bleed. Defaults: length 6 mm, offset 3 mm from the trim, 0.25 pt line. 3 mm matches the most common bleed allowance, so marks never land in the bleed area; 0.25 pt is visible yet thin enough for cutting accuracy.
  - `trim-line`: a hairline on the trim box edge, optional.
  - `grommet`: filled dots or crosshairs at positions computed by a placement rule: `inset` from the trim edge, a target `spacing`, always one at each corner, and evenly distributed between corners so the actual spacing is ≤ the target (no uneven final gap). Defaults: inset 25 mm, spacing 600 mm (roughly 2 ft, the common banner rule-of-thumb for wind load), dot 5 mm.
  - `sew-line` / `hem-line`: dashed line at a given offset from an edge (per-edge enable).
  - `fold-line`: dashed line at a given position, with optional tick marks outside the trim.
  - `custom`: a user-supplied single-page PDF or SVG symbol placed at named anchors (corners, edge midpoints, centre) or at a repeat interval.
- **FR2 Separation:** all marks are drawn in a dedicated optional-content group (OCG) named `BPS Marks` in a `Separation` colorant `BPS-Marks` (alternate: 100 % K), so a downstream RIP or operator can turn them off or route them. Users may choose `Registration` or process K instead.
- **FR3 Non-destructive:** marks are recorded as `MarkSpec` parameters on the job/layout. Regenerating output from the same inputs yields identical geometry.
- **FR4 Job label:** a text block plus an optional 2-D code, placed outside the trim on a chosen edge with a margin; the layout reserves the space (via Spec 003 margins) and warns if the medium is too narrow.
  - **Template language (ours):** Mustache-compatible `{{field}}` with a fixed, documented field list (`job.name`, `job.id`, `job.customer`, `item.widthMm`, `item.heightMm`, `copy.index`, `copy.total`, `panel.row`, `panel.col` (Spec 009), `media.name`, `device.name`, `date` (ISO 8601), `meta.<key>` for job ticket metadata) and filters `|upper`, `|mm`, `|in`. Unknown fields render empty with a warning. Mustache is chosen because it's logic-less, widely documented and has MIT-licensed implementations.
  - **Fonts:** one embedded open font (e.g. an OFL-licensed sans) so output is stable on every machine.
- **FR5 2-D code:** QR (default; ISO/IEC 18004, error correction M as a balance of density and damage tolerance) or Data Matrix. Payload is a URI `bps:job/<jobId>[/panel/<r>-<c>]` or an HTTPS URL to the server's job page, configurable. Minimum module size 0.5 mm so phone cameras and fixed scanners read it from a normal distance; a quiet zone of 4 modules per ISO/IEC 18004.
- **FR6 Presets:** `MarkPreset` objects (JSON) per hot folder or queue, overridable per job (Spec 007 editor) and exportable.
- **FR7 Metadata:** every mark's geometry and the label's code payload are written to the layout metadata (`/BPS_Layout` from Spec 003) so cut export (Spec 004) and finishing tablets can read them.

## Interfaces with existing packages and plugins
| Package | Change |
|---|---|
| `packages/nest` (003) | Calls `marks.draw()` through the existing `opts.marks` hook; margin reservation API `reserve(edge, mm)` |
| `packages/cut` (004) | Registration marks remain owned by 004; this spec composes with them and must not overlap their clearance zone (collision check, error) |
| `packages/core` | `MarkSpec`, `LabelSpec`, `MarkPreset` types in `JobTicket.finishing` |
| `apps/server` | `/mark-presets` CRUD; `GET /jobs/:id/label-preview.svg` |
| `CutterDriver/2` | Unchanged; may read `labelCode` from the `CutJob.options` for job lookup where a plugin documents it |

## Acceptance tests
1. **Unit (Vitest):**
   - Grommet placement: 2000 mm edge, inset 25, spacing 600 → 5 marks (4 gaps of 487.5 mm); property test (fast-check) that gaps are equal and ≤ spacing, and corners are always present.
   - Crop marks never intersect the bleed box (geometric check over random boxes).
   - Template: every documented field renders; unknown field renders empty plus a warning; HTML-escaping off, PDF string escaping on.
   - QR payload decodes (with an MIT/Apache decoder in tests) to the exact URI; module size ≥ 0.5 mm at the chosen size.
2. **PDF structure:** output contains the `BPS Marks` OCG and the `BPS-Marks` Separation; hiding the OCG and rendering with pdf.js yields pixels identical (±1/255) to the unmarked imposition inside the trim box.
3. **Differential (own fixtures):** for our fixture banners, compare mark geometry exported in `/BPS_Layout` to the hand-computed expected positions in `test/fixtures/expected-marks.json` within 0.05 mm.
4. **Collision:** a label configured on an edge already used by 004 registration rows fails validation with `MarkCollisionError` before rendering.
5. Lint, license check, vendor-neutral check pass.
